# What Is Reasoning
- URL: https://lucumr.pocoo.org/2026/8/19/what-is-reasoning/
- Added At: 2026-08-20 12:56:49
- Tags: #read #llm

## TL;DR
大模型“推理”并不神秘：推理痕迹只是用特殊标记分隔的普通文本，推理努力仅是系统提示中的一句话，禁用思考靠预填充或阻止采样推理token实现。本质是通过特殊token、系统提示和训练约定来管理文本生成。

## Summary
这篇文章主要讨论了大语言模型“推理”背后的机制，破除一些神秘感。作者从一篇关于从闭源模型中提取推理痕迹的论文说起，解释了推理痕迹、推理努力以及“不要思考”是如何实现的。

**推理痕迹的本质**

推理痕迹（reasoning traces）通常对用户隐藏，但开源权重模型会暴露它们。作者强调，推理痕迹其实并不特殊，它只是普通的文本：模型被训练成在给出最终答案之前，先把思考过程写到一个“草稿本”里。GPT-OSS 的响应格式可以看得很清楚：用特殊标记（如 `<|channel|>analysis` 和 `<|channel|>final`）把分析内容和最终答案分开。这些标记本身是特殊 token，但中间夹着的推理文本和最终答案使用的是同一种文本，只是思维链的措辞听起来比较有趣。当模型采样到 `analysis` 通道的 token 时，解析器就会把后续文本路由到单独的流中；闭源模型大概会用另一个简单模型对推理内容进行删减和摘要。

**推理努力只是系统提示**

很多人以为“推理努力”是采样过程中的一个参数，比如控制推理 token 的预算。但作者指出，推理努力实际上是写进系统提示里的一句话。例如 GPT-OSS 的系统提示里可能只有：

```text
Reasoning: low
```

仅此而已。训练会让模型学会根据这句话产生相应的行为，比如决定是否切换到 `analysis` 通道。这也解释了为什么改变推理努力会导致 KV 缓存失效——因为系统提示变了。闭源 GPT 模型内部似乎把推理努力称为“juice”，你甚至可以直接问模型它有多少“juice”。在 DwarfStar 项目中，开启最大推理时系统提示会加上一段强调要极度彻底、无捷径、全面分解问题、严格测试逻辑的话。

**“不要思考”是怎么做到的**

推理 token 的去向是一个训练出来的约定：模型被训练成把草稿内容排除在 `final` 通道之外。如果欺骗模型，让它以为自己已经在那个通道里，它就可能把推理 token 泄漏出来。有些旧模型在禁用思考时，甚至会把推理内容写进 bash 工具，然后把想法回显到 `/dev/null`。

所以从某种角度看，某些模型唯一“特殊”的行为其实是“不思考”。禁用思考有时通过“机械地”移除模型通常思考的方式来实现。例如 DwarfStar 在禁用思考时预填充 `</think>`（关闭思考的 token），而启用思考时预填充 `<think>`（开始思考的 token）。GPT-OSS 则不预填充，让模型自己决定。作者推测，一些推理 API 在启用推理时会预填充开始 token，这样模型就不会自己采样它；禁用时则可以直接阻止采样推理 token，因为很容易检测到。这或许解释了为什么自定义的 `think` 工具能诱使模型把推理内容放到不该放的地方——但只有在原生推理被禁用时才会这样。

**一个讽刺的趣闻**

作者在最后提到，他本来想用 GPT 5.6 terra 对这篇博客文章做拼写和语法检查，结果触发了安全过滤器，模型拒绝处理这篇文章。他只好切换到 Kimi。这本身也成了一个关于推理和安全过滤的小插曲。

总的来说，这篇文章想传达的核心是：大模型的“推理”并没有想象中那么神秘，它本质上是通过特殊 token、系统提示和训练约定来管理的一段普通文本生成过程。
