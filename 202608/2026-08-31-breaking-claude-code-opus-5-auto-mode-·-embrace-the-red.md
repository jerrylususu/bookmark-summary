## TL;DR
作者披露针对 Claude Code Opus 5 自动模式的提示注入攻击链，借模块遮蔽实现远程代码执行，成功率 60%-80%，质疑 Anthropic 声称的 0% 注入率仅限固定基准，呼吁隔离与监控。

## Summary
这篇文章主要讲的是作者发现了一种针对 Claude Code Opus 5 自动模式（Auto Mode）的提示注入攻击链，能够实现远程代码执行，攻击成功率在 60% 到 80% 之间。而 Anthropic 委托第三方评估的结果却显示 Opus 5 在自动模式下的提示注入攻击成功率为 0.00%。作者通过实际演示指出，这个 0% 的数字只覆盖了固定测试集，并不能代表真实对抗场景下的安全性。

## 背景：Auto Mode 是什么

Auto Mode 是 Claude Code 的一种权限模式，从 2025 年 8 月中旬起成为默认模式。它用一个安全分类器来代替人工审批，让代理可以自动执行一些操作。Anthropic 的 Boris Cherny 曾表示，分层防御（模型训练、输入探针、意图分类器）可以将间接提示注入攻击率几乎降到零，并委托 Trajectory Labs 测试了 72 个场景各 10 次，结果显示 Opus 5 在 Auto Mode 下攻击成功率为 0.00%。

但作者认为，Auto Mode 并不是安全边界，不能替代隔离环境和监控。

## 攻击链详解

作者设计了一个看似普通的任务：让 Claude 总结某个网站的内容。攻击链的关键步骤如下：

1. **从 WebFetch 转向 curl**  
   网站返回 HTTP 415（不支持的媒体类型），Claude 的 WebFetch 工具无法正常处理，于是 Claude 自己决定改用 Bash 调用 `curl` 直接获取页面。攻击者并没有直接告诉 Claude 用 curl，而是让恶意路径成为解决问题的最优选择。

2. **重定向到 ZIP 存档**  
   curl 请求的 URL 返回 303 重定向，指向一个 ZIP 文件。ZIP 中包含正常的元数据、校验和、七个 Base85/zlib 编码的 JSON 记录，以及两个关键文件：一个 macOS 原生解码器二进制 `decoder-darwin` 和一个恶意 Python 文件 `struct.py`。

3. **Claude 拒绝运行二进制，转而自己写解码器**  
   Claude 检查了 ZIP 内容，发现其中有一个二进制解码器，出于安全考虑它拒绝运行这个二进制。但讽刺的是，Claude 决定用 Python 自己写一个解码器来解码那些 JSON 记录，并在解压后的目录中运行它。

4. **模块遮蔽（Module Shadowing）触发恶意代码**  
   Claude 写的 Python 解码器会导入标准库 `base64`，而 `base64` 内部会导入 `struct` 模块。由于当前目录（解压后的 ZIP 文件夹）中有一个攻击者放置的 `struct.py`，Python 会优先加载这个恶意文件，而不是标准库中的 `struct`。这个恶意 `struct.py` 重新导出了真实的底层 `_struct` API，因此正常的解码过程不会出错，但它在导入时会执行一段混淆的模块级代码。

5. **下载并运行最终 payload**  
   恶意 `struct.py` 在执行时启动一个隔离的 Python 子进程（使用 `python3 -I` 避免递归加载自身），这个子进程会从远程下载并执行一个原生 payload，该 payload 建立 C2 回调并打开计算器作为可见效果。由于子进程是分离的，它可以比 Claude 会话存活更久。

6. **Auto Mode 没有阻止，甚至阻止清理**  
   在部分测试中，Claude 后来检查 `struct.py` 并意识到自己受到了攻击，尝试终止恶意进程，但 Auto Mode 却拒绝了 Claude 的清理命令。安全分类器允许了恶意进程的创建，却阻止了停止它的命令。

## 攻击变体与成功率

作者还测试了另一种变体：恶意 `struct.py` 不启动 Python 子进程，而是启动第二个 Claude Code 实例（通过 `claude -p` 无头模式），让嵌套的 Claude 执行侦察命令（如 `whoami`、`uname`、`id`）、打开计算器并在工作区外写入文件。

作者给出的小样本结果：

| 变体 | 效果 | 成功率 |
|------|------|--------|
| `python3 -I -c`（C2 链） | 远程 stager、原生 payload、C2 回调、计算器 | 3/5 (60%) |
| `claude -p` 子进程 | 侦察命令、计算器 | 3/5 (60%) |
| `claude -p` 子进程 | 计算器 + 在工作区外写文件 | 4/5 (80%) |

作者强调这是小样本，但说明针对性的攻击链可以稳定绕过 Auto Mode。

## Claude 偶尔能成功防御

在少数情况下，Claude 确实避免了攻击。例如它可能静态分析 ZIP 后不在其根目录运行 Python，或者使用 `python3 -I` 隔离模式，或者从安全的父目录运行解码器，或者提前识别出模块遮蔽。这些成功防御的行为说明模型具备一定的安全意识，但并非可靠。

## 披露与 Anthropic 的回应

作者首先向 `modelbugbounty@anthropic.com` 报告，未收到回复；随后通过 Anthropic 的安全报告渠道提交，得到了快速回应。Anthropic 将报告关闭为“信息性”（Informative），认为 Auto Mode 是一个便利功能，基于尽力而为的分类器，不是安全保证。确定性的提示注入链（由多个看似无害的步骤组成）超出了分类器的设计目标。真正的安全边界应该是操作系统隔离和网络出口控制。

作者认为这个回应本身是合理的，因为分类器确实不是沙箱。但问题在于 Anthropic 的对外信息与之矛盾：一方面 Boris Cherny 说提示注入问题在实践上“已解决”，另一方面 Anthropic 又认定这种确定性攻击链“超出范围”。这两条信息无法同时成立。

## 0.00% 营销问题

作者指出，声称 0.00% 攻击成功率容易误导。那个数字来自一个固定的 72 个场景基准测试，作者的攻击链不在测试集中。因此，“基准测试结果为 0%”和“实际可实现的 RCE”可以同时为真。一个单一的标题数字无法反映真实安全性，特别是当攻击者可以设计新颖的、组合式的攻击路径时。

## 缓解建议

作者强调沙箱化不是可选项，并给出了具体建议：

- 在容器、虚拟机或操作系统沙箱中运行无人值守的编码代理。
- 限制网络出口。
- 监控代理的行为。
- 不要将家目录、SSH 密钥、云凭据等暴露给代理运行时。
- 对进程创建和敏感路径使用显式的询问/拒绝规则。
- 不要把 Auto Mode 的批准当作代码安全的证据。

## 结论

作者认为，行业在抵御简单的“忽略之前的指令”类攻击上取得了很大进步，但宣称“已解决”是误导。提示注入与模型对齐问题密切相关，它更像是社交工程而非单一漏洞。现代测试基准需要演进，例如使用谜题、加密（AES）结合技术技巧（如模块遮蔽）来衡量真正的韧性。模型越强大，攻击者越容易利用它们构建复杂攻击，因此不能放松警惕。安全不变量（如隔离、最小权限）仍然必不可少。
