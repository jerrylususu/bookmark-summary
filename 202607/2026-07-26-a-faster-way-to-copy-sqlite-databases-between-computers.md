# A faster way to copy SQLite databases between computers
- URL: https://alexwlchan.net/2025/copying-sqlite-databases/
- Added At: 2026-07-26 06:14:02
- Tags: #read #tips

## TL;DR
使用 `rsync` 直接传输大型 SQLite 数据库缓慢且易损坏。改用 `.dump` 导出为 SQL 文本，索引仅存命令，压缩后体积大幅缩小，再通过 SSH 和 rsync 传输，本地重建数据库，既提速又可靠。

## Summary
在远程服务器上复制大型 SQLite 数据库到本地时，直接使用 `rsync` 会因数据库体积大（尤其是索引占用大量空间）导致传输缓慢，且中途若发生写入还可能造成文件损坏。本文作者发现，利用 SQLite 自带的 `.dump` 命令，可以将整个数据库导出为纯 SQL 文本文件，在这个过程中，庞大的索引数据只被保留为一句 `CREATE INDEX` 的指令，而非重复存储实际数据，因此文本文件比原始数据库小很多；再加上文本内容高度重复，非常适合压缩（例如 gzip 可将其进一步压缩至原来的十几分之一），从而大幅减少需要传输的数据量。同时，先转储再拷贝的方式保证了拷贝源是静态文件，彻底避免了因数据库持续写入而可能出现的“磁盘映像损坏”错误。最后他展示了具体操作流程：通过 `ssh` 在服务器上执行 `sqlite3` 转储并压缩，用 `rsync` 下载压缩包，本地解压后重新导入生成完整的数据库。这种方法既加快了拷贝速度，又提升了传输过程的可靠性。
