# Jev means structured output is interesting again
- URL: https://www.seangoedecke.com/jev-means-structured-output-is-interesting-again/
- Added At: 2026-09-16 13:54:54
- Tags: #read #llm

## TL;DR
Jev 是仅输出结构化结果的低延迟系统1模型，可用于实时决策，或成智能计算原语；但其技术门槛不高，普通大模型单令牌推理也能接近，智能上限有限，“免疫幻觉”存疑，价值仍待验证。

## Summary
Jev 是一款“系统1”风格的 AI 模型：它接收人类语言输入，但不生成人类语言输出，只输出结构化结果，比如从给定选项里选一个答案。文章作者认为，这类模型的接口设计很有意思，可能让结构化输出重新变得有价值。

它和普通 LLM 的关键区别在于：普通 LLM 是自回归的，一个 token 一个 token 地生成，所以慢且行为难以预测；Jev 只做结构化输出，可以在一次前向传播中并行回答许多问题，因此速度很快——最快约 70 毫秒，最慢也就 500 毫秒。这种低延迟让它能实时玩《毁灭战士》：把游戏状态和可选项喂进去，让它决定按键、目标等，它就能在实时环境下做出决策。作者觉得这一点最令人兴奋：快速的结构化输出可能成为一种新的“智能计算原语”，让人们能在各种决策点注入廉价、低延迟的智能，从而催生非聊天机器人的新应用。

不过作者也提出质疑：快速结构化输出其实已经能做到。普通 LLM 的结构化输出慢，主要是因为没多少人真正在意，且想要大块 JSON 的人通常用“语法约束解码”，仍然走自回归。如果只需要在有限选项里做选择，完全可以预填充 `"choice": "`，然后只生成一个受约束的 token，再配合批处理并行推理，就能获得接近 Jev 的速度、一致性和并行性。已经有人在 Jev 发布后尝试这种做法，效果尚可。作者因此怀疑 Jev 没有太深的技术护城河，其他实验室或个人开发者可能很容易复刻类似模型。当然，Jev 仍可能因为专门针对结构化输出做微调而优于粗糙的“Qwen-32B-System-One”式改造。

在智能水平上，作者认为 Jev 大概不会达到前沿 LLM 的水平，因为它完全不能用测试时计算，这会把这类模型的上限限制在非推理型 LLM 附近。对低延迟应用来说这问题不大，但不该把它看作新的扩展轴或提升智能的途径。至于 Jev 开发者声称的“免疫幻觉”，作者觉得这是语义上的回避：Jev 仍然可能选错，比如把天空选成红色。它只是从用户提供的选项里挑，而不是凭空编造，但这和普通 LLM 的结构化输出没有本质区别，并不会让它更可靠。

结论是：Jev 的价值有多少来自模型本身、多少来自“每题只生成一个 token”的推理策略，还不清楚。发布中的数据与演示，看起来用任何 Terra 规模的模型接入单 token 推理栈也能做出来。作者希望 Jev 成功，也希望快速结构化输出领域出现真正的竞争，推动大实验室发布专门微调过的官方模型，比如 GPT-5.6-Terra-System-One，那会是非常适合构建 AI 产品的模型。
