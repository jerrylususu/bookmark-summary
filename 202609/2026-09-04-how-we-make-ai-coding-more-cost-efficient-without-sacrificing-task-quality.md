# How we make AI coding more cost efficient without sacrificing task quality
- URL: https://github.blog/ai-and-ml/github-copilot/how-we-make-ai-coding-more-cost-efficient-without-sacrificing-task-quality/
- Added At: 2026-09-04 02:53:20
- Tags: #read #agent

## TL;DR
GitHub Copilot通过四项优化降低编码代理成本：选择性压缩噪声、移除行号、精简提示词、直接返回后台任务结果。强调从整体任务完成衡量，局部省token可能引发更多恢复操作。改动均经离线与在线实验验证，核心是移除模型不必要工作。

## Summary
优化 AI 编码代理的效率，关键在于从“整个任务完成”的角度衡量，而不是只看单次工具调用的 token 数量。有时节省局部 token 反而会让模型反复恢复被删掉的信息，导致整体更慢、更贵。

文章介绍了 GitHub Copilot 在不牺牲任务质量的前提下降低成本的四个实际改动：

## 1. 选择性压缩输出，保留有用上下文

早期尝试用 RTK 这类工具缩短 shell 输出，结果发现模型会为了找回被压缩掉的细节而重新读取文件或重跑命令，整体反而更费 token、更慢。因此团队采用了更保守的策略：

- 对 `cat`、`git diff`、`git show` 以及任意脚本输出保持原样，因为这些内容通常包含关键信息。
- 对 `grep` 等搜索结果只做无损重组，不丢弃任何匹配项。
- 只对安装、构建、测试、进度等重复性噪声进行选择性压缩，并且保留完整原始输出，模型可以通过恢复路径取回。

效果：离线基准测试中任务成功率没有显著下降，在线实验成本平均下降约 5.5%。

## 2. 移除不产生价值的格式化内容

`view` 工具以前会给每一行代码加上行号前缀，但现在的编辑工具已经不再使用行号来定位修改，而是匹配代码上下文。这些行号在每次读取文件时都会累积，白白占用上下文窗口。

移除行号前缀后，文件内容本身不变，模型推理成本在离线测试中下降约 5%，在线实验平均每日每用户推理成本下降约 3%，质量指标没有退化。

## 3. 压缩提示词，但保留关键行为

`task` 工具的提示词经过多次迭代后变得冗长。团队使用元提示循环让 Copilot 自己压缩提示，最初压缩到约原来一半。

但第一次在线实验出现回归：原本允许并行运行独立代理的指导被改成了严格的顺序调度，导致自定义代理变成串行执行。团队立即停止实验，补充行为回归测试，最终用一句话替换了原来的复杂规则：

> 独立代理可以并行运行；考虑副作用。

最终提示词每轮减少约 1300 个 token，占每次会话总提示 token 的约 1.8%，活跃小时标准化成本降低约 2.9%，并且没有检测到质量回归。

## 4. 直接交付后台任务结果，消除多余检索轮次

后台任务（例如长时间运行的 shell 命令或子代理调查）完成时，旧机制只是唤醒模型告知“完成了”，但不附上结果，模型必须再花一轮去取。多个任务同时完成时，这种浪费会更明显。

现在系统会批量合并完成通知，并直接把结果以工具返回的格式发给模型。模型可以立刻继续工作，无需额外检索。

这样减少了模型轮次，也避免了把完整会话上下文传递到不必要的调用中。AI 信用成本平均降低约 2.3%。

## 方法：离线评估 + 在线实验

每个改动都先在离线基准测试中评估，再通过在线 A/B 实验验证，最后才发布。文章还指出，在某个产品上有效的优化不一定适用于另一个产品——例如 Copilot 代码审查中有效的一份更紧凑的文件工具指令，在 Copilot CLI 上反而增加了成本，因此没有上线。

## 五个核心教训

1. **优化整个完成的任务，而不是单次工具调用。** 局部缩短输出可能迫使模型做更多恢复工作。
2. **优化编排，不只是优化模型输出。** 能由系统确定性完成的工作，就不要让模型额外消耗轮次。
3. **压缩要看内容类型。** 保留精确信息，优先无损转换，并监控模型使用恢复路径的频率。
4. **重写提示词可能带来意外后果。** 必须用行为测试验证关键行为是否保留。
5. **证据是特定于工作负载的。** 每个改动都要在离线基准、在线实验和实际产品环境中重新评估。

总的来说，这些优化没有让模型变得更聪明，而是移除了模型本来就不需要做的额外工作，从而在保持任务质量的同时降低成本。
