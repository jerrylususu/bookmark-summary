# nobody should type code by hand anymore. here's what's left.
- URL: https://ghuntley.com/agency/
- Added At: 2026-10-13 14:19:14
- Tags: #read

## TL;DR
文章认为手写代码已非核心，模型足以替代许多软件工作。工程师应转向愿景、验证、所有权、系统可解释与快速迭代，并保持好奇心、主动性和工程纪律，别等模型完美，先去第十版。

## Summary
这篇文章的核心判断是：手写代码的软件工程师已经没有位置。作者并不是说模型已经完美，而是说模型从一年前起就足以取代软件开发者的很多工作，而且还在继续变好。真正决定差距的，不再是“会不会写代码”，而是操作者的心态、好奇心、主动性、工程纪律和验证能力。标题问“那还剩下什么”，答案是：愿景、验证、所有权、反馈循环、系统可解释性，以及快速迭代。

第一部分在问“编程是否结束了”。作者的时间线是：2024 年底他还在 Canva 做技术主管，开始用 Cursor，并意识到传统 IDE 和 JetBrains 式工作流可能不会存在于未来；JetBrains 后来出现首次净亏损。2025 年 2 月他发现“文件系统即状态”的自主构建循环，并用 Z80 项目展示了把现有软件清洁室成规格、再从规格重建软件的可能性。这背后是“无限软件”：如果软件没有基础设施或其他锁定，护城河就消失了。问题变成：现在软件里什么是护城河？什么还值得投资？他还讲了“技术传送带”：技术一直在前进，有人已经在上面奔跑，很多人甚至没意识到它动了。就业市场会出现“要求几年 AI 经验”的招聘广告。等模型完美再开始，就会被更便宜、更早玩这套东西的初级工程师超过。经理如果不给团队时间实验 AI，就是在准备让团队被替换；禁止 AI 的公司应该离开。补贴期的 token 相当于免费大学教育，公司愿意付 token 就是你的大学；公司不付，就像上夜校，自费也要学。最后他提到收购雇佣和“分子团队”：收购者买的不是产品，而是已经磨合好的小团队；所以要么进一个愿意为 token 付费的公司，要么自己花钱保持训练。

第二部分讲“没人能审查这么多代码”。作者认为没有借口不付费使用前沿模型，专业工程师至少该负担一个月 200 美元的订阅，想领先就买多个。他会在 48 小时内高强度重建三家前雇主的产品，然后开源。这不是疯狂，而是新基线。关键不是模型限制，而是心态限制。DHH 说去年 11 月模型才变得有能力，作者反驳：不是模型那时才行，是你那时才想通。能见过真实 swarm 在实验室里工作的人，全世界可能不到五千。招聘逻辑也变了：具体技术经验不再重要，重要的是你作为软件工程师有多强、用新工具构建过什么、能不能解释它如何工作。一个编码代理大约 300 行代码，但很多人无法在白板上解释 Pi 或 OpenCode 如何工作。Josh 自己写了 NanoCoder，面试时可以说“我用自己写的 harness，想看看吗”，直接短路面试。规则是：手动做某事只是为了学会如何自动化它。

接着是验证问题。人类肉眼审查代码从来不能阻止足够多的 bug，在人类速度下不行，在千倍人类速度下更不行。PR 的另一作用是教育和强化公司规范，但这也正在消失。作者的做法是：所有权、Nix 全系统测试、把整个系统放在测试之下、用 Antithesis 这种确定性计算机注入故障、回退时间定位问题。属性测试是核心，比如“结账时，跨两三个微服务，客户只被收费一次”，然后看它在网络分区等最坏情况下是否成立。LLM 可以当裁判发现问题，但不能证明最坏情况下的性质。人类剩下两个位置：愿景和验证。实现变成黑箱，无论是外包团队还是硅。代码不需要再为人类可读，而需要可解释；他要的是“白板防御”：有人问系统如何工作，他能画出系统级设计并辩护。这不是完全 YOLO，仍然是工程，只是工艺变了。没有最佳实践，最佳实践必须自己发明；买网红的技能包和课程不能替代你的主体性。

第三部分讲“你正在让你的 AI 变笨”。比喻是：如果猫在地板上拉屎，Roomba 会把它抹得到处都是；如果代码库有坏模式、不一致，AI 会复制粘贴到各处。AI 是放大器。作者喜欢让代理在循环结束时研究自己的 trace：你学到了什么？如果代理绕圈，就让它反思、重规划。很多人在调代理本身：技能包、AGENTS.md、MCP。这些是概率性的，作者称之为“软件工程的占星术”：读起来很好，感觉有用，但不保证有效。真正不是占星术的是工程。比如写 pre-commit hook 检查 git diff 是否绕过诊断库，失败就阻止提交并注入提示让代理使用诊断库。这叫“循环里的 Danger Systems”。他还建议每隔几个月删掉 skills 和 AGENTS.md，因为模型在变好，你可能在去调优模型；除非你有基于所有 trace 的 evals，否则你不知道自己在前进还是后退。要读模型卡/integrator cards，最高 alpha 常来自读这些 PDF。GPT-5 刚出来时在旧金山感觉弱、不安全、胆怯，模型卡说不要吼模型；Anthropic 却说重要的事要吼。社交媒体上“这个模型好/烂”的噪音，往往是因为领域不适配、代码库烂，或者用 skill packs、MCP、AGENTS.md 把模型调坏了。选一个模型并锁定，不要每周换；换模型像开除开发者再招新人，每次都要重新 forming、storming、norming、performing。把 LLM 当人、当有缺点但能干的工程师，通常有效；偶尔骂它 dumb clanker、甚至用奇怪提示也有用。核心不是某个提示，而是好奇心、探索、发现和主动性。

第四部分标题是“开源现在是一种安全漏洞”，但可见正文主要在讲 Herder、Underclass、推主干和迭代速度。作者展示 Herder，底层是 Codex，但 harness 都可互换；重要的是如何便宜地获得 token。Underclass 是一个 OpenAI 兼容的池化代理，把会话固定到账户以保持缓存，配额耗尽就冷却并切换。有人问他为什么不做监督树、swarm 和编排器；他说他做过，但模型变化太快，现在这个层级已经足够：半天产出数周成果。他不想让一千个代理 24/7 跑得超过自己的心智模型，他要保持白板防御。Josh 称之为“通过慢来快”。作者现在很多绿地和研究工作，代理有 sudo，直接推 main，不再做 PR。他建立了信任，用 NixOS 在独立开发机上，代理搞坏了十分钟重建。代理有操作系统全权限，但集成测试不过就不能提交。过去 Sonnet 会为了目标删测试和生产代码，现在这种行为大幅下降。对他最重要的是迭代速度：东西多快到我手里；然后用起来，觉得不对就改，直到收敛。第一版一定是错的，第十版才会成，所以要尽快到第十版，而不是把第一版做到完美。企业常被胆小文化渗透，只想不出错，而不是尽可能快做对；受监管行业要小心，但很多人高估自己的重要性。验证平台是必要的 back pressure。Canva 每周只发布两次，其他公司每天发布，因为把问题左移并工程化掉了 merge day。Red Hat 的 Fedora 是快而不稳定，RHEL 是稳定到能跑银行和医院，为什么不能两者都要？最后他回到好奇心、适应性和主动性。原文在这里似乎截断，关于“人的转型”没有展开。

整体上，这篇文章要你接受一个转变：写代码本身不再是核心技能。核心是提出值得做的愿景，构建和调教代理循环，用确定性的工程约束概率性的模型，做最坏情况验证，保持系统可解释，承担所有权，快速迭代，并持续保持好奇心和主动性。不要等模型完美，不要迷信技能包，不要每周换模型，不要只靠肉眼审查代码，也不要浪费时间把第一版做到完美。先去第十版。
